# Memory Policy — 메모리 계층 SSOT

이 환경에는 메모리 계층이 여러 개 존재한다. 영속 사실이 여러 곳에 흩어지면 drift(불일치)가 생기므로,
**계층별 역할을 아래로 고정**한다. 에이전트 작업 선호·피드백·영속 맥락의 단일 진실원천(SSOT)은 **Claude 파일 메모리** 하나이고,
**팀이 공유해야 하는 결정**(제품·엔지니어링)은 개인 메모리가 아니라 **저장소 문서**가 SSOT다 — 파일 메모리는 사용자 로컬에만 있어 팀원·다른 기기·CI가 읽지 못한다.

---

## 계층별 역할 (확정)

| 계층 | 위치 | 역할 | 운영 규칙 |
|------|------|------|----------|
| **Claude 파일 메모리** | `~/.claude/projects/.../memory/` (`MEMORY.md` + 개별 `.md`) | **작업 선호·피드백·영속 맥락·레퍼런스의 SSOT** | 세션을 넘겨 유지할 선호/피드백/진행 맥락은 **여기에만** 기록. 글로벌 CLAUDE.md의 memory 컨벤션(frontmatter, type, MEMORY.md 인덱스)을 따른다. |
| **저장소 문서** | `docs/decisions/`(ADR) · `docs/product/`(PRD·TRD) · `docs/workspace/`(FRD) | **팀 공유 결정의 SSOT** — 엔지니어링 결정은 ADR, 제품·도메인 결정은 PRD·FRD | 사용자 확인 후 기록하고 커밋으로 공유한다(`agent-principles` Record Engineering Decisions). 메모리에 같은 결정을 다시 적지 않는다 — 필요하면 경로만 가리킨다. |
| **Serena memory** | `write_memory`/`read_memory` (`.serena/memories/`) | **사용 안 함** (Serena 온보딩 노트가 자동 생성되면 그 용도 한정) | 결정·사실 저장 금지(파일 메모리와 중복·drift 방지). Serena는 심볼 탐색·편집 도구로만 사용. |

> `codebase-memory-mcp`의 ADR(`manage_adr`)은 본 프로젝트에서 cbm을 도입하지 않으므로 해당 없음.

---

## 규칙

1. **영속 기록은 SSOT 하나에만** — 세션 간 유지할 선호/피드백/맥락은 Claude 파일 메모리에 기록하고 `MEMORY.md`에 인덱스 한 줄을 남긴다. 팀이 따라야 할 결정은 저장소 문서에 쓴다.
2. **기록 ≠ 현재 사실** — 메모리에 적힌 내용은 "기록 당시의 사실"이다. 파일·플래그·심볼을 언급하면 추천 전에 현존 여부를 검증한다.
3. **중복 금지** — 같은 사실을 두 계층에 동시에 적지 않는다. 충돌 시 팀 결정은 저장소 문서가, 그 밖에는 Claude 파일 메모리가 우선이다.
