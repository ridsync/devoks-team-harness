# product-interview — 제품 기획 정련 (PRD 앞단)

막연한 제품 아이디어를 바로 PRD로 옮기면 처음 떠오른 해결책이 요구사항으로 굳고, "누구의 어떤 문제인가"와
"하지 않을 것"이 빈 채로 수십 개의 기능이 쌓인다. 이 스킬은 PRD를 쓰기 **전**에 대화로 착수 점검 7문항을 채우고,
그 결과를 **PRD 입력 양식**(`../product-prd-author/assets/PRD.intake.md`) 그대로의 정련 요약으로 만들어
`devoks-sdlc:product-prd-author`에 넘긴다. 사용자가 양식을 직접 채워 오면 이 인터뷰는 필요 없다 — 같은 양식이기 때문이다.

## 범위 (중요)

| 입력 상태 | 쓸 스킬 |
|---|---|
| 제품 아이디어만 있음 / 누구의 어떤 문제인지(1번)가 비었거나 방향이 갈림 | **이 스킬** → 승인 후 prd-author 자동 연결 |
| 정리된 기획서 또는 채운 `PRD.intake.md` | `devoks-sdlc:product-prd-author` (1번이 비면 그 스킬이 이 스킬로 진입, 7번만 비면 제안으로 확인) |
| 기능 하나의 의도가 막연함 | `devoks-sdlc:feature-interview` |

- **HITL 전용** — 질문이 사용자에게 전달되지 않는 맥락(위임받은 서브에이전트, `/loop`, 자동 파이프라인)에서는 실행하지 않고 "기획 의도 불명확 — 사용자 확인 필요"를 blocker로 보고한다.
- 하지 않는 것: PRD 작성(FR·NFR·백로그), 시장 조사, 기술 설계, 코드.

## 호출 방법

```
/devoks-sdlc:product-interview [ask=<아이디어 본문|문서 경로> (default: 대화 맥락)] [out=<디렉터리> (default: docs/product)]
```

> 표기: `key=값` 필수 · `[key=값]` 선택 · `(default: X)` 미지정 시 X로 진행.

- `out`은 prd-author로 그대로 넘긴다.

## 절차

질문 기법(예시 대화·실패 패턴·변형안 렌즈·평가 3축·가정 점검)은 `../feature-interview/references/interview-techniques.md`를 공유한다 — 기능 단위 예시를 제품 단위로 읽으면 된다.

### 1. 가설·확신도 + 7문항 판정

첫 응답에서 현재 이해를 **한 문장 가설**과 **확신도(%)**로 적고, 입력을 7문항(`../product-prd-author/references/prd-guide.md` §1)에 대조해 **확정 / 부분 / 미확정** 한 줄씩 보여준다. 확신도는 정직해야 한다 — 다음 질문 3개에 대한 반응을 예측할 수 없다면 숫자가 높을 수 없다.

### 2. 의도 공백은 하나씩, 사실 공백은 마지막에 한 번에

- **의도 공백(1 누구의 어떤 문제 · 3 대안 대비 차이 · 7 하지 않을 것)** — 한 메시지에 질문 1개, `예상: <가설 답과 근거>`를 붙인다. 일반 텍스트로 묻는다(선택지를 주면 답의 범위가 미리 좁아진다). 사용자가 "알아서 해"로 결정을 넘길 때만 구체 선택지 2개를 제시한다.
- 해결책·관습 표현("앱 만들어서", "보통 서비스들처럼")이 문제 자리에 오면 "그게 없다면 지금 무엇이 불편한가요?"로 탐침한다 — 해결책은 "원하는 기능"란으로 옮겨 두고 버리지 않는다.
- 무엇을 만들지 **방향이 여러 갈래**면 HMW 한 문장 → 변형안 5~8개 → 의미 있게 다른 방향 2~3개 → 방향별 숨은 가정 순으로 좁힌다(기법 문서 B절). 사용자가 하나를 고를 때까지 기다린다.
- **사실·슬롯 공백(2 현재 방식 · 4 지표 · 5 제약 · 6 가정)** — 의도가 정해진 뒤 한 번에 모아 묻고, 모르면 "미확정"으로 둔다. 목표치·담당·일정은 묻지 않는다(양식에 없다).

### 3. 멈춤 조건

1·3·7번이 확정이고 다음 질문 3개에 대한 반응을 예측할 수 있으면 4단계로 간다. 몇 차례 물어도 확신도가 오르지 않으면 질문이 틀린 것이다 — 그렇게 말하고 프레임을 바꾼다.

### 4. 정련 요약 — PRD 입력 양식 그대로

`../product-prd-author/assets/PRD.intake.md`의 구조로 채워 보여준다(주석 블록은 뺀다). 대화에서 나오지 않은 값은 지어내지 않는다 — "미확정". 원래 요청 원문을 첫 줄에 남긴다. 끝에 "이대로 PRD 작성으로 넘어갈까요? 고칠 부분이 있으면 말씀해 주세요."를 붙인다.

**★ 1·7번은 미확정으로 승인할 수 없다** — 대상 없는 PRD는 기능 목록이 되고, 하지 않을 것이 없으면 범위가 매 회의마다 다시 열린다.

### 5. 명시 승인 → prd-author로 바로 이어서

- 통과는 요약을 그대로 받아들인다는 명시 표현("네"·"좋아요, 진행해 주세요" 등)뿐이다. "알아서 해주세요"는 결정 위임이므로 선택지 2개로 다시 묻는다. 수정이 오면 반영해 4단계를 다시 보여준다.
- 승인되면 **같은 흐름에서** Skill 도구로 `devoks-sdlc:product-prd-author`를 실행한다 — `src`는 생략(기본값 "대화 맥락" = 방금 승인된 요약), `out`을 받았으면 함께 넘긴다. prd-author의 게이트에서 진입했으면 새로 호출하지 않고 그 절차로 돌아간다.
- 사용자가 "정리만 하고 PRD는 나중에"라고 하면 `<out>/PRD.intake.md`로 요약을 저장하고(이미 있으면 덮어쓰지 않고 날짜를 붙인 새 파일) 멈춘다. 나중에 `/devoks-sdlc:product-prd-author src=<out>/PRD.intake.md`로 이어간다.

## 완료 기준

- 첫 턴에 가설·확신도·7문항 판정이 있었다.
- 의도 질문은 한 번에 하나씩 예상 답과 함께 나갔고, 사실 공백은 한 번에 모아 물었다.
- 정련 요약이 PRD.intake 양식이고, 1·7번이 채워졌고, 사용자가 명시적으로 승인했다.
- 승인 직후 prd-author(또는 진입한 호출자 절차)로 이어졌다 — 보류 요청이면 `PRD.intake.md`로 저장됐다.
