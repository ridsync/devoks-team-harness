# 인터뷰 예시와 실패 패턴

> 출처: addyosmani/agent-skills `interview-me`(2026-10 검토)를 하네스 Define 단계에 맞춰 옮겨 적었다.
> 도메인은 예시일 뿐이다.

## 예시 — 요청이 다른 산출물로 바뀌는 경우

```
사용자: 우리 지표용 대시보드 만들어줘

에이전트:
가설: 스탠드업에서 "요즘 어때?"에 답할 방법을 원하고, "대시보드"는 떠오른 관습적 답이다.
확신도: ~30% — 누구를 위한 것인지, "지표"가 무엇인지, 성공 모습이 비어 있음

Q: "요즘 어때?"를 묻는 사람이 누구인가요 — 본인, 스탠드업의 개발팀, 아니면 윗선(매니저·임원)?
예상: 스탠드업의 개발팀. "우리"는 보통 그 범위이고, 임원용이면 지표와 표현이 크게 달라져서요.

사용자: 사실 저 혼자 봐요. 어떤 실험이 돌고 있고 초기 신호가 어떤지 자꾸 놓쳐서요.

에이전트:
갱신: 팀 대시보드가 아니라 개인 실험 트래커. 확신도 ~60% — "초기 신호"의 의미와 완료 모습이 비어 있음

Q: 문제가 "어떤 실험이 있는지 모르는 것"인가요, "결과를 한곳에서 못 보는 것"인가요?
예상: 두 번째. 목록은 어딘가 있는데 결과가 도구 다섯 곳에 흩어져 있어 손으로 맞추는 게 지겨운 것.

사용자: 첫 번째예요. 목록 자체가 없어요. 문서 여기저기 흩어져 있어요.
```

질문 두 개 만에 산출물이 "대시보드"에서 "목록"으로 바뀌었다. 대시보드를 만들었다면 틀렸을 것이다.

## 실패 패턴 (발견하면 멈추고 고친다)

| 패턴 | 왜 문제인가 |
|---|---|
| 한 메시지에 질문 3개 이상 | 인터뷰가 아니라 설문이다. 사용자는 훑어 읽고 표면적으로 답한다 |
| 예상 답 없는 질문 | 내 가정이 드러나지 않는다 — 인터뷰의 목적이 그 가정을 드러내는 것이다 |
| "알아서 해주세요"를 최종 답으로 받음 | 위임이지 결정이 아니다. 구체 선택지 2개로 다시 묻는다 |
| 승인 전에 FRD·PLAN·코드를 만들기 시작 | 승인되지 않은 의도 위에 쌓는 것 — 되돌리는 비용이 가장 큰 시점에 오류를 고정한다 |
| 승인 직후 같은 턴에 다음 스킬 실행 | 다음 단계 선택권은 사용자에게 있다 |
| "확장 가능하게" 같은 답을 그대로 받음 | 모범답안일 수 있다 — "실제로 뭘 원하세요?"로 탐침 |
| 세 라운드가 지나도 확신도가 안 오름 | 질문이 틀렸다 — 물러나 프레임을 바꾼다 |
| Out of scope 줄 생략 | "만들지 않을 것"에 대한 불일치가 구현 끝에 터진다 |
| 승인 전에 `FRD.draft.md` 기록 | 문서가 사용자가 하지 않은 승인을 암시한다 |
