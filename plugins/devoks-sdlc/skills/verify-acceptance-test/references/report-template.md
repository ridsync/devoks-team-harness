## 심각도 기준

심각도 SSOT는 `.claude/refs/code-review.md` §8(Critical/High/Medium/Low)이다. 아래는 실동작 검증 맥락으로 좁힌 특수화이며 축은 같다 — 다른 등급명(`Major`/`Minor` 등)을 쓰지 않는다. 구현 후 체크리스트의 **안전 인터록이 Critical/High로 커밋을 멈추므로** 등급명이 어긋나면 인터록이 작동하지 않는다.

| 심각도 | 기준 |
|--------|------|
| Critical | 잘못된 값이 영속됨·다른 레코드를 덮어씀(데이터 손실/오염), 권한 경계 우회 |
| High | AC 기대 동작이 성립하지 않음 — UI 상태 또는 영속 상태 FAIL(**FAIL 판정은 최소 High**) |
| Medium | AC는 성립하지만 부수 이상 — 콘솔 에러, 중복 요청, 눈에 띄는 지연 |
| Low | 문구·표시의 미세 차이(AC 판정에 영향 없음) |

`⚠️ 검증 환경 갭`·`➖ 영속 확인 불충분`은 기능 결함이 아니므로 심각도를 붙이지 않는다.

## 작성 팁

- 시나리오 표는 Phase 0에서 만든 표를 그대로 이어받는다 — 새로 설계하지 않는다.
- FAIL은 반드시 증거(스크린샷 파일명, 조회한 실제 값)와 함께 남긴다. "안 되는 것 같다"는 결론이 아니다.
- 커버리지 줄은 메인 루프가 Phase 0 선별 결과로 채운다(에이전트는 시나리오 표만 받으므로 모른다). §9 표가 없는 FRD면 "§9 없음 — 선별 기준으로 <N>개"로 적는다.
- 검증 환경 갭과 FAIL을 섞지 않는다 — 갭은 "환경이 상태를 재현 못함", FAIL은 "기능이 실제로 틀림".
