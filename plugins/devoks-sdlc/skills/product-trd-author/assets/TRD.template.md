### 3.1 앱 내부 아키텍처
> 프레임워크가 정해진 앱(배포 단위)마다 한 번. 여러 기능이 같은 경로로 데이터를 읽고 바꾸도록 **목표 구조**를 고정한다 — 기능 하나 안의 파일 구성은 FRD §4. 경로·폴더 이름은 이 프로젝트가 고른 값이며, 결과는 project convention 구조 슬롯(S1~S5)의 1차 근거가 된다(`/devoks-core:setup-project-convention` 7단계).

- **근거 문서:** <프레임워크 공식 권장 문서 — 예: 프로젝트 구조·데이터 보안·인증 가이드 (확인일)>
- **현행과의 관계:** <greenfield: 해당 없음 / brownfield: 현행 = 목표 · 아래 "현행 vs 목표" 표 참조>

**디렉터리 맵 (목표)**

| 디렉터리 | 역할 | 두지 않는 것 |
|---|---|---|
| <예: 라우팅 진입점> | | <예: DB 직접 접근> |

**계층과 의존 방향:** <예: 진입점 → 서비스 → 데이터 접근 계층 → 인프라. 역방향·건너뛰기 금지 — 예외가 있으면 사유>

**진입점별 데이터 접근**
